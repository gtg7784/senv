# senv ユーザーマニュアル

> 暗号化された `.env` の代替 — Rust で実装され、平文 `.env` と同じ手軽さ。

---

## 5 分でスタート

```bash
# 1. ビルド (Homebrew 公開前まで)
cd senv
cargo build --release
sudo cp target/release/senv /usr/local/bin/   # または PATH の通ったディレクトリへ

# 2. プロジェクトに移動して初期化
cd my-project
senv init                       # age 鍵生成 + OS Keyring 保存 + 空の .env.age 作成

# 3. 既存の .env があれば一行で移行
senv import .env
rm .env                          # 平文はもう不要

# 4. 日常利用 — コマンドの前に `senv --` をつけるだけ
senv -- cargo run
senv -- npm run dev
senv -- pytest

# 5. 編集は TUI で
senv                             # TUI 起動
# → ↑↓ / j / k で行移動
# → e で値を編集、a で追加、q で終了
```

以上です。詳細は以下。

## 主要概念

| 用語 | 意味 |
|---|---|
| **identity (アイデンティティ)** | age x25519 鍵ペア。秘密鍵は OS Keyring、公開鍵 (`age1...`) は vault に保存 |
| **recipient (受信者)** | vault を復号できる公開鍵。複数登録 = チーム |
| **vault** | `.env.age` ファイル。JSON + 各値ごとの age 暗号文 + BLAKE3 MAC |
| **keyring** | OS 標準の秘密保管庫。macOS Keychain、Linux Secret Service、Windows Credential Manager |

基本ルール: **平文 `.env` はディスクに置かない。** git にコミットするのは `.env.age` のみ。どこかで復号するには、そのマシンの keyring に秘密鍵が必要。

## CLI コマンド全体

```bash
senv init                        # 初回鍵生成 + 空の vault 作成
senv import <file>               # 平文 .env を vault に暗号化
senv list                        # cwd の .env キー一覧 (値はバイト長のみ、マスク)
senv diff                        # .env.example との missing/extra 比較
senv export                      # eval $(senv export) で現在のシェルに注入
senv -- <command>                # vault env を注入して子プロセスを起動
senv                             # 引数なし = TUI
senv tui                         # 明示的に TUI
senv --help
senv --version
```

### `senv -- <cmd>` が本命

毎日使うコマンド。任意のツールの前に `senv --` を付けると、vault のすべての secret が子プロセスの環境変数として注入されます。

```bash
senv -- cargo run
senv -- npm test
senv -- python manage.py runserver
senv -- docker compose up
senv -- gh issue create
```

子プロセスは親 (`senv`) の env を継承し、vault の値が上書きされます。終了コードはそのまま伝播 (CI フレンドリー)。

### キーマップ

| キー | 動作 |
|---|---|
| `↑↓` / `j` / `k` | 行移動 |
| `t` / `T` | 環境タブ切り替え (dev/staging/prod) |
| `space` | 選択行の値を表示/マスク切り替え |
| `e` | 値を編集 — モーダル起動、`Enter` で保存、`Esc` でキャンセル |
| `a` | 新しい secret を追加 — `KEY=VALUE` を入力して `Enter` |
| `d` | 削除 (確認あり) |
| `s` | schema description (説明) を編集 — vault に一緒に保存される |
| `r` | recipients (チームメンバー) の追加/削除 |
| `i` | `.env` import ウィザード — プレビュー後に一括暗号化 |
| `D` | `.env.example` との diff 表示 (Missing/Extra/OK) |
| `L` / `U` | 即座に lock / unlock |
| `?` / `F1` | help オーバーレイ |
| `q` / `Ctrl+C` | 終了 |

### 起動直後に画面が空のとき

vault に secret が 0 件のとき、中央にプレースホルダーが表示されます。この状態では `j/k` で移動する行がないので動きません (これは仕様)。先に `i` (import) か `a` (追加) でデータを入れてください。

## チームでの利用

### 新しいメンバーを追加する

**新メンバー (自分のマシンで)**
```bash
git clone <repo> && cd <repo>
senv init                                 # 自分の age 鍵を生成
# 出力に自分の公開鍵が表示される:
#   recipient: age1ttttgkfg...
# この行を Slack 等で管理者に送る
```

**管理者 (vault オーナー)**
```bash
senv                                       # TUI 起動
# → r (Recipients)
# → a (入力モード)
# → "age1ttttgkfg..." を貼り付け
# → Enter

# すべての secret が両方の鍵で即座に再暗号化される
git add .env.age
git commit -m "share secrets with @them"
git push
```

**新メンバー (再び自分のマシンで)**
```bash
git pull
senv                                       # 自動 unlock、すべての secret が見える
```

### メンバーから権限を取り消す

```bash
senv                                       # TUI
# → r → j/k で離れるメンバーを選択 → d (revoke)
# → vault 全体が残りのメンバーの鍵のみで再暗号化される
git add .env.age && git commit -m "revoke @them" && git push
```

> ⚠️ **重要**: revoke は新しい vault だけを保護します。離れたメンバーが持つ過去の git 履歴は、彼らの鍵で依然として復号可能です。**真の取り消しには、secret 値自体もローテーションしてください** (DB パスワード変更、API キー再発行など)。その後 senv の `e` で新しい値を入力。

## なぜ安全なのか (要約)

1. **age 非対称暗号** — 公開鍵で施錠、秘密鍵で開錠。パスワードではなく数学的な鍵。総当たり不可能。
2. **秘密鍵は OS keyring のみ** — ディスクに平文の鍵ファイルなし。ノート PC ロックと一緒に施錠。
3. **`.env.age` は git に commit しても安全** — recipients に登録された人だけが復号可能。公開リポジトリでも OK。
4. **BLAKE3 MAC** — vault 改ざんを即座に検出。unlock 拒否。
5. **atomic write + 0600 権限** — クラッシュ安全 + 他ユーザーは読めない。
6. **Symlink 拒否** — 攻撃者が vault パスを別の場所にリダイレクトできない。
7. **メモリ zeroize** — secret はメモリ使用後すぐ 0 で上書き (coredump/swap 保護)。

詳細な脅威モデル: [README の Security model セクション](../README.md#security-model)を参照。

## トラブルシューティング

### `senv init` 後 TUI を起動しても何も表示されない

→ 正常。vault には secret が 0 件。`a` で追加するか `senv import .env` を実行。

### `j/k` が効かない

→ 行が 0 件だから。先にデータを入れてください (`a` か `i`)。`q`/`?` はモードキーなのでデータがなくても動きます。

### ハイライト (選択行強調) が見えない

→ シアン背景 + 黒文字 + 太字 + `▶ ` シンボル。ターミナルがシアンを不可視にレンダリングする場合、issue で報告してください (テーマ切り替えを追加します)。

### `senv -- cargo run` 時に keyring プロンプトが出た

→ macOS の初回 unlock 時に Keychain アクセス許可を求めます。**常に許可** を選べば以後出ません。

### 新しいマシンに移動したら vault が開けない

→ 秘密鍵は OS keyring に保存されており、自動では移動しません。二つの選択肢:
1. **新マシンで `senv init` → 古いマシンから vault に新公開鍵を追加** (`r` → `a`)
2. **既存の鍵を export/import** — 現在未実装。v2 予定。

### CI / コンテナ環境で keyring がない

→ 現在未対応。次回リリース予定 (`SENV_IDENTITY` env var で秘密鍵を注入)。

### `.env.age` が誰かに見られたら?

→ ciphertext が見えるだけ。recipients に秘密鍵がない人は何も読めません。**ただし key 名 (例: `DATABASE_URL`) は見えます。** 名前すら隠したい場合は vault をプライベートリポにのみ置いてください。

### `q` で終了しない

→ `Ctrl+C` を試す。それでも駄目なら modal 内 — まず `Esc` で modal を抜けてから `q`。

## FAQ

**Q. `dotenvx` や `1Password CLI` と何が違う?**

A. 三つの違い:
1. **TUI** — 他は CLI のみ。senv は TUI が一級市民で、schema/recipients/diff の視覚編集が可能。
2. **Rust 単一バイナリ** — Node/Python ランタイム不要。2.5MB。
3. **OS keyring + age** — dotenvx は `.env.keys` に秘密鍵を平文保存。senv は keyring のみ (`security delete-generic-password` でいつでも掃除可能)。

**Q. Linux/Windows でも動く?**

A. Linux は OK (`linux-keyutils` バックエンド)。Windows はコード準備済みだが、まだリリースバイナリなし。次のマイルストーン予定。

**Q. `.env.age` を安全にバックアップするには?**

A. git に commit すれば OK — すでに暗号化されているので公開バックアップも可。秘密鍵は別途バックアップ推奨:
```bash
# macOS Keychain から senv identity を export
security find-generic-password -s senv -a default-identity -w
# → AGE-SECRET-KEY-1... が出力。安全な場所に保管 (紙、1Password 等)
```

**Q. 同じマシン上の複数プロジェクトで同じ keyring entry を使う?**

A. 現在はそうです (`service=senv`、`account=default-identity`)。一つのマスター鍵で全プロジェクトの vault が開きます。プロジェクトごとの分離 (`account=<project-fingerprint>`) は v2 予定。
