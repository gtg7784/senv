# senv 使用说明

> 加密的 `.env` 替代方案 — 用 Rust 编写,使用体验和明文 `.env` 一样顺畅。

---

## 5 分钟快速开始

```bash
# 1. 编译 (在 Homebrew 发布之前)
cd senv
cargo build --release
sudo cp target/release/senv /usr/local/bin/   # 或任何在 PATH 中的目录

# 2. 进入项目并初始化
cd my-project
senv init                       # 生成 age 密钥 + 存入 OS keyring + 创建空的 .env.age

# 3. 如果已有 .env,一行命令迁移
senv import .env
rm .env                          # 明文不再需要

# 4. 日常使用 — 任何命令前加 `senv --`
senv -- cargo run
senv -- npm run dev
senv -- pytest

# 5. 在 TUI 中交互编辑
senv                             # 启动 TUI
# → 方向键 / j / k 在行间移动
# → e 编辑值,a 添加,q 退出
```

就这么简单。详细说明见下。

## 核心概念

| 术语 | 含义 |
|---|---|
| **identity (身份)** | age x25519 密钥对。私钥存于 OS keyring,公钥 (`age1...`) 写入 vault |
| **recipient (接收者)** | 可以解密 vault 的公钥。多个接收者 = 团队 |
| **vault (保险库)** | `.env.age` 文件。JSON + 每个值的 age 密文 + BLAKE3 MAC |
| **keyring (密钥环)** | 操作系统原生的密钥存储:macOS Keychain、Linux Secret Service、Windows Credential Manager |

核心规则: **磁盘上不放明文 `.env`。** 只有 `.env.age` 提交到 git。要在任何机器上解密,你的私钥必须在该机器的 keyring 里。

## CLI 命令一览

```bash
senv init                        # 首次生成密钥 + 创建空 vault
senv import <file>               # 把明文 .env 加密到 vault
senv list                        # 当前目录 .env 键的列表 (值只显示字节数,带掩码)
senv diff                        # 与 .env.example 的差异 (missing/extra)
senv export                      # eval $(senv export) 注入到当前 shell
senv -- <command>                # 给子进程注入 vault env 后执行
senv                             # 无参 = TUI
senv tui                         # 显式启动 TUI
senv --help
senv --version
```

### `senv -- <cmd>` 是主力命令

每天都会用。在任何工具前加 `senv --`,vault 里所有 secret 会作为环境变量注入子进程。

```bash
senv -- cargo run
senv -- npm test
senv -- python manage.py runserver
senv -- docker compose up
senv -- gh issue create
```

子进程继承父进程 (`senv`) 的环境变量,vault 的内容覆盖在上层。退出码原样传递 (CI 友好)。

### 按键映射

| 按键 | 动作 |
|---|---|
| `↑↓` / `j` / `k` | 行间移动 |
| `t` / `T` | 切换环境标签 (dev/staging/prod) |
| `space` | 显示/掩码切换当前值 |
| `e` | 编辑值 — 弹出 modal,`Enter` 保存,`Esc` 取消 |
| `a` | 添加新 secret — 输入 `KEY=VALUE` 后按 `Enter` |
| `d` | 删除 (需确认) |
| `s` | 编辑 schema description (说明) — 与 vault 一起保存 |
| `r` | 管理 recipients (团队成员添加/删除) |
| `i` | `.env` import 向导 — 预览后批量加密 |
| `D` | 与 `.env.example` 的 diff 视图 (Missing/Extra/OK) |
| `L` / `U` | 立即 lock / unlock |
| `?` / `F1` | 帮助覆盖层 |
| `q` / `Ctrl+C` | 退出 |

### 首次启动看到空白时

vault 中 secret 数量为 0 时,屏幕中央会显示占位提示。此状态下 `j/k` 没有行可移动 (这是设计如此)。先用 `i` (import) 或 `a` (添加) 录入数据。

## 团队协作

### 添加新成员

**新成员 (在自己的机器上)**
```bash
git clone <repo> && cd <repo>
senv init                                 # 生成自己的 age 密钥
# 输出中显示自己的公钥:
#   recipient: age1ttttgkfg...
# 通过 Slack 等发给管理员
```

**管理员 (vault 持有者)**
```bash
senv                                       # 启动 TUI
# → r (Recipients)
# → a (输入模式)
# → 粘贴 "age1ttttgkfg..."
# → Enter

# 所有 secret 立即用两方密钥重新加密
git add .env.age
git commit -m "share secrets with @them"
git push
```

**新成员 (回到自己的机器)**
```bash
git pull
senv                                       # 自动 unlock,所有 secret 可见
```

### 撤销成员权限

```bash
senv                                       # TUI
# → r → j/k 选中要离开的成员 → d (撤销)
# → vault 整体仅用剩余成员的密钥重新加密
git add .env.age && git commit -m "revoke @them" && git push
```

> ⚠️ **重要**: 撤销仅保护新的 vault。离开成员持有的过往 git 历史依然可以用他们的密钥解密。**真正的撤销需同时轮换 secret 值本身** (修改数据库密码、重新签发 API 密钥等)。然后在 senv 中用 `e` 输入新值。

## 为什么安全 (摘要)

1. **age 非对称加密** — 公钥锁,私钥开。是数学密钥,不是口令。暴力破解不可行。
2. **私钥只存在 OS keyring** — 磁盘上没有明文密钥文件。系统锁屏即上锁。
3. **`.env.age` 可放心 commit** — 只有 recipients 名单上的人能解密。即使公开仓库也安全。
4. **BLAKE3 MAC** — 即时检测篡改。unlock 拒绝继续。
5. **原子写入 + 0600 权限** — 崩溃安全 + 其他用户读不到。
6. **拒绝 Symlink** — 攻击者无法把 vault 路径重定向到别处。
7. **内存清零** — secret 在内存中用完后立即用 0 覆写 (防 coredump/swap 泄漏)。

完整威胁模型: [README 的 Security model 节](../README.md#security-model)。

## 故障排查

### `senv init` 之后启动 TUI 什么都没显示

→ 正常。vault 里 secret 为 0 个。用 `a` 添加或 `senv import .env`。

### `j/k` 不起作用

→ 因为行数是 0。先录入数据 (`a` 或 `i`)。`q`/`?` 是 mode 键,即使没数据也能用。

### 高亮 (选中行强调) 看不到

→ 是青色背景 + 黑色文字 + 加粗 + `▶ ` 符号。如果终端把青色渲染成不可见,请提 issue,我会加主题切换。

### `senv -- cargo run` 时弹出 keyring 提示

→ macOS 首次 unlock 时会询问 Keychain 访问权限。选 **始终允许**,下次不再询问。

### 换了新机器,vault 打不开了

→ 私钥在 OS keyring 里,不会自动跟随。两个选择:
1. **新机器上 `senv init` → 从旧机器把新公钥加进 vault** (`r` → `a`)
2. **导出/导入已有密钥** — 当前未实现,计划 v2。

### CI / 容器环境没有 keyring

→ 当前未支持。下次发布计划: `SENV_IDENTITY` env var 注入私钥。

### `.env.age` 被人拿到怎么办?

→ 他只能看到 ciphertext。私钥不在 recipients 名单上的人什么都读不到。**不过 key 的名字 (如 `DATABASE_URL`) 是可见的。** 如果连名字都要隐藏,请把 vault 放在私有仓库。

### `q` 退不出

→ 试 `Ctrl+C`。还不行说明你在 modal 里 — 先 `Esc` 退出 modal,再 `q`。

## 常见问题

**Q. 和 `dotenvx` 或 `1Password CLI` 有什么不同?**

A. 三点:
1. **TUI** — 别的工具只有 CLI。senv 把 TUI 当成一级公民,schema/recipients/diff 都能可视化编辑。
2. **单个 Rust 二进制** — 不需要 Node/Python 运行时。2.5MB。
3. **OS keyring + age** — dotenvx 把私钥明文存在 `.env.keys`。senv 只存 keyring (用 `security delete-generic-password` 随时清理)。

**Q. 在 Linux/Windows 上能用吗?**

A. Linux 可以 (`linux-keyutils` 后端)。Windows 代码就绪但还没有发布的二进制。下个里程碑发布。

**Q. 如何安全备份 `.env.age`?**

A. 提交到 git 就行 — 它本身就是加密的,公开备份也 OK。私钥另外备份:
```bash
# 从 macOS Keychain 导出 senv identity
security find-generic-password -s senv -a default-identity -w
# → 输出 AGE-SECRET-KEY-1... 保存到安全的地方 (纸、1Password)
```

**Q. 同一台机器上的多个项目共用一个 keyring entry 吗?**

A. 当前是这样 (`service=senv`、`account=default-identity`)。一把主密钥能开本机所有项目的 vault。按项目隔离 (`account=<project-fingerprint>`) 计划 v2 实现。
