# senv 사용 설명서

> 평문 `.env`를 쓰지 않고도 `.env` 만큼 편하게 — Rust로 만든 암호화 환경변수 도구.

---

## 5분 빠른 시작

```bash
# 1. 빌드 (Homebrew 배포 전까지)
cd senv
cargo build --release
sudo cp target/release/senv /usr/local/bin/   # 또는 PATH에 잡힌 폴더

# 2. 어느 프로젝트로 가서 초기화
cd my-project
senv init                       # age 키 생성 + OS keyring 저장 + 빈 .env.age 생성

# 3. 기존 .env가 있으면 한 줄로 마이그레이션
senv import .env
rm .env                          # 평문은 더 이상 필요 없음

# 4. 일상 사용 — 앞에 senv -- 만 붙이세요
senv -- cargo run
senv -- npm run dev
senv -- pytest

# 5. 편집은 TUI에서
senv                             # TUI 열림
# → 화살표/j/k 로 행 이동
# → e 로 값 편집, a 로 추가, q 로 종료
```

이게 다입니다. 더 자세한 건 아래.

## 기본 개념

| 용어 | 뜻 |
|---|---|
| **identity (정체)** | age x25519 키 쌍. private는 OS keyring에, public(`age1...`)은 vault에 저장 |
| **recipient (수신자)** | vault를 풀 수 있는 public key. 여러 명 등록 = 팀 |
| **vault** | `.env.age` 파일. JSON + 각 값마다 age로 암호화된 ciphertext + BLAKE3 MAC |
| **keyring** | OS의 기본 비밀 저장소. macOS Keychain, Linux Secret Service, Windows Credential Manager |

핵심 룰: **평문 `.env`는 disk에 두지 않습니다.** `.env.age`만 git에 commit. 어디서든 풀려면 그 사람의 private key가 keyring에 있어야 함.

## CLI 명령어 전체

```bash
senv init                        # 첫 키 + 빈 vault 생성
senv import <file>               # 평문 .env를 vault로 암호화
senv list                        # cwd의 .env 키 목록 (값은 byte 길이만, 마스킹)
senv diff                        # .env.example 대비 missing/extra
senv export                      # eval $(senv export) 로 현재 shell에 주입
senv -- <command>                # 자식 프로세스에 vault env 주입하고 실행
senv                             # 인자 없으면 TUI
senv tui                         # 명시적 TUI
senv --help
senv --version
```

### `senv -- <cmd>` 가 핵심

이게 일상 명령. 어떤 도구든 앞에 `senv --` 만 붙이면 vault의 모든 secret이 자식 프로세스 환경변수로 들어갑니다.

```bash
senv -- cargo run
senv -- npm test
senv -- python manage.py runserver
senv -- docker compose up
senv -- gh issue create
```

자식 프로세스는 부모(`senv`)의 env를 그대로 상속받고, 거기에 vault 내용이 위에 얹어집니다. 종료 코드는 그대로 전파됩니다 (CI 친화적).

### 키맵

| 키 | 동작 |
|---|---|
| `↑↓` / `j` / `k` | 행 이동 |
| `t` / `T` | 환경 탭 이동 (dev/staging/prod) |
| `space` | 선택한 값 보이기/마스킹 토글 |
| `e` | 값 편집 — modal 열림, 수정 후 `Enter` 저장 / `Esc` 취소 |
| `a` | 새 secret 추가 — `KEY=VALUE` 입력 후 `Enter` |
| `d` | 삭제 (확인 후) |
| `s` | schema description 편집 — vault에 함께 저장됨 |
| `r` | recipients 관리 (팀원 추가/삭제) |
| `i` | `.env` import wizard — 평문 .env 발견 시 미리보기 후 일괄 암호화 |
| `D` | `.env.example` 대비 diff (Missing/Extra/OK 시각화) |
| `L` / `U` | 즉시 lock / unlock |
| `?` / `F1` | help overlay |
| `q` / `Ctrl+C` | 종료 |

### 처음 띄우면 빈 화면이 보일 때

상황: vault에 secret이 0개일 때 화면 가운데 메시지가 뜸. 이 상태에서는 `j/k`가 누를 행이 없어서 동작 안 함 (정상).

해결: `i` (import) 또는 `a` (직접 추가) 키로 데이터를 먼저 넣으세요.

## 팀 협업

### 새 팀원 추가하기

**팀원 (본인 컴퓨터에서)**
```bash
git clone <repo> && cd <repo>
senv init                                 # 자기 age 키 만들기
# 출력에 자기 public key 보임:
#   recipient: age1ttttgkfg...
# 이 줄을 Slack 등으로 너에게 전달
```

**나 (vault 관리자)**
```bash
senv                                       # TUI 열림
# → r (Recipients)
# → a (입력 모드)
# → "age1ttttgkfg..." 붙여넣기
# → Enter

# 즉시 모든 secret이 두 사람 키로 재암호화됨
git add .env.age
git commit -m "share secrets with @them"
git push
```

**팀원 (다시 본인 컴퓨터에서)**
```bash
git pull
senv                                       # 자동 unlock, 모든 secret 보임
```

### 팀원 권한 회수

```bash
senv                                       # TUI
# → r → j/k 로 떠나는 팀원 선택 → d (revoke)
# → vault 전체가 남은 사람들 키로만 재암호화됨
git add .env.age && git commit -m "revoke @them" && git push
```

> ⚠️ **중요**: revoke는 새 vault만 보호합니다. 그 팀원이 가진 이전 git history는 그들의 키로 여전히 풀립니다. **진짜 안전하려면 secret 값 자체도 바꾸세요** (DB 비밀번호 변경, API 키 재발급 등). 그 후 senv에서 `e` 키로 새 값 입력.

## 보안이 왜 안전한가 (요약)

1. **age 비대칭 암호화** — public key로 잠그고 private key로 푸는 구조. 패스워드가 아니라 수학적 키. 브루트포스 불가능.
2. **private key는 OS keyring에만** — 디스크에 평문 키 파일 없음. 노트북 잠금되면 같이 잠김.
3. **`.env.age`는 git에 commit해도 안전** — recipients에 등록된 사람만 풀 수 있음. 공개 레포에 올라가도 OK.
4. **BLAKE3 MAC** — vault 변조 즉시 감지. unlock 거부.
5. **atomic write + 0600 권한** — 크래시 안전 + 다른 사용자 못 읽음.
6. **Symlink 거부** — 공격자가 vault 경로를 다른 곳으로 link 시킬 수 없음.
7. **메모리 zeroize** — secret이 메모리에 떴다가 즉시 0으로 덮어쓰임 (coredump/swap 보호).

상세 위협 모델은 [README의 Security model 섹션](../README.md#security-model)을 보세요.

## 트러블슈팅

### `senv init` 했는데 `senv` 띄우면 빈 화면

→ 정상. vault가 비어있어서 그럼. `a`로 추가하거나 `senv import .env` 하세요.

### `j/k` 가 안 먹힘

→ rows가 0개라서 누를 게 없는 거. `a`나 `i`로 먼저 데이터를 넣으세요. `q`/`?`는 mode 키라서 데이터 없어도 동작합니다.

### highlight (선택된 행 강조)가 안 보임

→ 시안색 배경 + 검정 글자 + bold + `▶ ` symbol입니다. 만약 안 보이면 터미널 테마가 시안색을 invisible로 처리하는 거. 이슈로 알려주세요.

### `senv -- cargo run` 했는데 keyring prompt 떴다

→ 첫 unlock 시 macOS는 Keychain 접근 권한을 한 번 묻습니다. **항상 허용** 하면 다음부터 무차단.

### 새 컴퓨터로 옮겼는데 vault를 못 풀음

→ private key는 OS keyring에 있어서 다른 머신으로 자동 이동 안 됨. 두 방법:
1. **다른 머신에서 `senv init` 후 자기 새 public key를 vault에 추가** (`r` → `a` from 원래 머신)
2. **기존 키를 export/import** — 현재 미구현. v2 예정.

### CI/배포 환경에서 keyring 없음

→ 현재 미구현. 다음 release 예정 (`SENV_IDENTITY` env var로 private key 주입).

### `.env.age` git commit 했는데 누군가 풀어서 봐?

→ recipients에 등록된 사람만 풉니다. 외부인은 ciphertext만 보임. **다만 vault 내용 자체가 누구에게나 보이는 건 사실**이니, 어떤 키들이 있는지(예: `DATABASE_URL`)도 공개되는 게 싫다면 vault 파일을 private repo에만 두세요.

### `q`로 안 끝남

→ `Ctrl+C` 시도. 그래도 안 되면 modal 안에 있는 거 (modal 안에서는 q가 단순 입력). `Esc`로 modal 빠져나온 뒤 `q`.

## 자주 묻는 질문

**Q. `dotenvx`나 `1Password CLI`랑 뭐가 달라요?**

A. 세 가지 차이:
1. **TUI** — 다른 도구는 CLI만. senv는 TUI가 1급 시민이라 schema/recipients/diff 시각 편집 가능.
2. **Rust 단일 바이너리** — Node/Python 런타임 없음. 2.5MB.
3. **OS keyring + age 조합** — dotenvx는 `.env.keys`에 private key를 평문 보관. senv는 keyring에만 (`security delete-generic-password`로 정리 가능).

**Q. Linux/Windows에서도 동작해요?**

A. Linux는 됩니다 (`linux-keyutils` 사용). Windows는 코드는 준비됐지만 아직 release binary 없음. 다음 마일스톤.

**Q. `.env.age`를 안전하게 백업하려면?**

A. git에 commit하면 됩니다 — 어차피 암호화돼 있어서 공개 백업 OK. 추가로 private key는 별도 백업 추천:
```bash
# macOS Keychain에서 senv identity export
security find-generic-password -s senv -a default-identity -w
# → AGE-SECRET-KEY-1... 출력. 안전한 곳에 보관 (e.g. 종이, 1Password)
```

**Q. 한 머신에 여러 프로젝트가 있는데 같은 keyring entry 써요?**

A. 현재는 그렇습니다 (`service=senv`, `account=default-identity`). 즉 같은 마스터 키로 모든 프로젝트 vault를 풀음. 프로젝트별 분리 모드는 v2 예정 (`account=<project-fingerprint>`).
